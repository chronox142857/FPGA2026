# 首版验收方法与信号源

本清单对照最初开发计划，起始基线为`analyzer-st7735s-integrated-20261031`。2026-10-31已执行同板UART短线回接，发现并修正窗口边界及错误停止位后的帧对齐；最终结果见VALIDATION.md及发布证据。下面的通过条件仍是验收标准，不能将未执行项目当作已经通过。

## 如何认定功能完成

每项功能分别记录：源码实现、自动化测试、真实硬件验证。只有代码和仿真不能代替整机实测；屏幕出现协议名称也不能单独证明解码正确。

每次测试留存：固件版本、接线照片、信号源设置和预期字节、采样/触发配置、原始采样导出、实际解析结果、通过/失败及原因。自动识别测试使用AUTO，手动指定协议/角色/参数只用于独立核对解码。

| 验收项 | 操作 | 通过条件 |
|---|---|---|
| 采样数据 | 输入已知高低电平和已知周期脉冲，覆盖8通道、5档采样率和掩码 | 原始数据逐点/按边沿核对；禁用通道为0；有效点数32768 |
| 缓存/触发 | 四类触发、四档预触发，触发前等待足够长以发生回绕 | 触发索引为0/8192/16384/24576；数据时序连续；完成后冻结；取消/重新启动行为正确 |
| 时间 | 核对首样本、触发样本、分频与边沿时间，并改变输入相位 | 元数据关系符合INTERFACE.md；误差按同步延迟、采样量化及实际时钟精度解释 |
| UART | 已知数据，9,600～1,000,000 baud，8N1 | AUTO中包含合理UART候选；完整帧数据与源相同；速率符合采样分辨率 |
| I²C | 已知地址/数据，100k/400k/1MHz，读写、重复START、ACK/NACK | 地址、方向、字节和事件顺序正确；NACK含义按事务判断 |
| SPI | 已知收发数据，四种模式，逐步提高至5MHz | 自动保留合理候选并报告歧义；已知角色/模式下逐字节核对正确 |
| 通道角色 | 改变协议信号接入候选通道的顺序 | AUTO重新判断角色；SPI无法确定的方向/模式允许多个候选 |
| 异常/未知 | UART坏停止位、截断事务、稳定高/低电平、固定非协议测试集 | 错误被标记；静态输入UNKNOWN；信息不足不得强行唯一确定 |
| 界面/按键 | 查看真实波形、缩放、移动、解析翻页、设置、KEY1长按 | 显示与导出数据一致；窄脉冲缩小后仍有活动标记；设置作用于下一次记录 |
| 单次/循环 | 启动、等待、取消、重复，实物连续执行至少100次 | 无死锁、无旧记录混入；记录完成次数/数据编号可核对 |
| 串口 | 设置参数并dump | 导出点数、掩码、时间基准和采样内容正确 |
| 最终演示 | 三类协议各完成采集→识别→解析→显示，再展示异常和未知 | 录像、接线和导出记录可以复现；手动模式不计作自动识别成功 |

100次连续采集是实物验收项，已有100次缩小深度仿真不能替代。识别率/误判统计应注明固定测试集、样本数及是否存在歧义，不能宣称能唯一识别任意波形。

## 第一阶段：板载FPGA自测源

现有`rtl/la_testgen.v`已实现以下三种模式，复位后默认关闭，设置TEST GEN并启动采集后生效：

| 源 | 目前实际支持 | 已知预期 |
|---|---|---|
| UART | 约115200 baud，8N1；可注入停止位错误 | 连续完整字节按0x13递增；窗口截取位置不同，首字节不一定为0x55 |
| I²C | 100kHz，模拟整条总线波形 | 原始地址字节A0，即7位地址0x50、写；一个变化的数据字节及ACK |
| SPI | 100kHz，模式0～3，低有效CS | 8位MSB优先；MISO与MOSI逐字节按位取反 |

这里I²C的ACK和SPI的MISO由发生器模拟，没有连接真实从机。当前自测源不是任意波特率/时钟可调的通用发生器；最高速率与更多边界激励需要扩展源或使用独立设备。

先关闭电源接短线，接好后上电并重新下载整机程序；已有小屏线保持不变。球位名称以J3丝印定位，不是连接器数字针号。

| 信号 | 自测输出 | 采集输入 |
|---|---|---|
| UART TX / I²C SCL / SPI SCK | P15 | W18，CH0 |
| I²C SDA / SPI MOSI | P16 | W19，CH1 |
| SPI MISO | V16 | R16，CH2 |
| SPI CSn | W16 | R17，CH3 |

UART只需第一根线；I²C需前两根线，SCL/SDA各通过约4.7kΩ上拉到3.3V作为短线100kHz起点；SPI用四根线。同板天然共地，独立设备还必须共地。I²C更高速度时必须核对上升沿，不能保证这组电阻适合所有线长和负载。

串口测试命令和按键方法见USER_GUIDE.md。第一个UART案例建议：

```text
rate 5
mask 01
group 01
proto 0
trigger 2 0
pre 1
test 1 0
run
```

预期32768点、UART约115200 baud、完整字节按0x13递增；通过波形页、解析页和dump同时核对。完成后再按USER_GUIDE.md执行I²C、SPI四模式、错误UART和UNKNOWN案例。

同板回接验证了输出引脚→导线→采集引脚→缓存→ARM→分析→显示，但采集与源共用时钟、源也是自编代码，不能单独证明异步信号适应性、真实通信兼容性或绝对频率精度。

### 自动保存真实回接记录

`scripts/selftest_jtag.py`使用实际ARM ELF符号及ARM编译的结构偏移，比较运行代码与ELF后，设置正常应用的配置与循环标志。正常主循环负责触发、读取BRAM和解码；脚本不注入采样数据。每个记录同时保存ARM样本、冻结BRAM、元数据、候选、事件和独立已知源核对结果。

```text
python scripts/selftest_jtag.py --protocol uart --count 100 --cycle-pre
python scripts/selftest_jtag.py --protocol uart-error --count 8 --cycle-pre
python scripts/selftest_jtag.py --protocol spi --mode 0
python scripts/selftest_jtag.py --protocol spi --mode 0 --manual-spi
```

SPI需在正确四根短线下分别执行模式0～3：AUTO检查保留实际角色/模式并报告歧义，手动模式逐字节与已知物理信号核对。手动通过不能代替自动识别通过。I2C脚本入口不代表已经完成接线或实测。

默认检查当前SDK源码与工程一致；恢复发布文件但SDK不是对应版本时，可用`--release-commit`及`--release-directory`绑定对应Git标签和产物目录，偏移取自该提交的头文件，不从其他实验源码猜测。

每轮结果页强制整屏重画；此措施用于本轮观察，不是局部刷新或刷新率优化。测试器会短暂停ARM导出证据并恢复运行，正常捕获之间不重新配置FPGA；失败时保存原始文件及failure.json，不把失败计入通过。

## 第二阶段：独立信号源交叉验证

优先使用已有的3.3V单片机开发板，不必为第一阶段购买设备。具体引脚与固件按实际型号确定。

- UART：单片机硬件UART，或确认TX为3.3V逻辑的USB转TTL模块，周期发送固定字节和递增编号；TX接采集通道，GND共地。普通USB转TTL模块不能当作I²C/SPI发生器。
- I²C：单片机主机与一个已有、地址已知的传感器/EEPROM等从机构成真实总线，分析仪只监听SCL/SDA。不要在没有从机时期待ACK和后续完整数据。也可用单片机GPIO独立生成整条开漏测试波形，但记录为模拟源测试。
- SPI：单片机主机与从机通信，监听SCK/MOSI/MISO/CS。若暂时没有从机，可将主机MOSI回接到其MISO输入做已知回环，观察两路相同的数据；此案例不能证明收发方向可被唯一识别。
- GPIO/定时器：生成已知脉宽、相位、组合电平或故意破坏的帧，覆盖触发、异常和未知案例。普通硬件UART往往不能直接产生坏停止位，可改用GPIO/定时器模拟。

单片机信号源建议发送固定同步数据、递增计数、变化数据，独立保存预期内容；采用硬件外设/定时器，避免不受控的软件延时。源与分析仪使用不同晶振可以检验异步采样。更严格的时序/速率验证，再借助示波器或参考逻辑分析仪，并记录其设置和测量范围。

实现参考：Raspberry Pi官方pico-examples提供UART/I²C/SPI工程；ST官方提供STM32 I²C与SPI入门示例。型号未定前不指定单片机接脚、不假定所有板子都能产生最高目标速率。

- https://github.com/raspberrypi/pico-examples
- https://wiki.st.com/stm32mcu/wiki/Getting_started_with_I2C
- https://wiki.st.com/stm32mcu/wiki/Getting_started_with_SPI

外部输入仅接与所选FPGA IO Bank匹配的电平；当前接线使用3.3V逻辑。不能把5V TTL或RS232/RS485/CAN物理层直接接入采集脚。不同设备独立供电时先确认共地，不随意互接供电输出。

## 采样率和记录长度

采样率必须满足软件要求：每位/时钟周期至少10个采样点。同时必须保证记录窗口够长，以观察完整帧和空闲/事务边界；UART自动识别至少需要3个有效帧。

| 采样率 | 32768点覆盖时间 |
|---|---:|
| 1MSa/s | 32.768ms |
| 5MSa/s | 6.5536ms |
| 10MSa/s | 3.2768ms |
| 25MSa/s | 1.31072ms |
| 50MSa/s | 0.65536ms |

因此9600 baud建议先用1MSa/s；115200 baud、100kHz I²C/SPI可先用5MSa/s；5MHz SPI需50MSa/s。低速信号使用最高采样率反而可能因窗口太短无法识别。稳定低/高电平测试应使用确定电平，不能把悬空当作UNKNOWN标准；某些周期波形本身可能存在合法协议解释，也不能一概要求所有PWM都必须UNKNOWN。

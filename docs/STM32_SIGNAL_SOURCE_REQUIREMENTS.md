# STM32 独立协议信号源开发要求

版本：2026-10-31。本文可以整份交给另一个开发对话，按此需求完成单片机工程。这里只开发外部信号源，FPGA 主项目由原对话维护。

## 1. 任务与分工

请为用户实际持有的 STM32 开发板编写一个可独立运行的数字协议测试信号源，用于验证 FPGA 逻辑分析仪。输出标准 **UART、I²C、SPI** 波形以及可控的异常/静态信号，发送内容必须已知、可重复、可逐字节核对。

首要目标是形成能编译、下载、实际输出的工程，不能仅交付伪代码、函数片段或未经编译的示例。STM32 固件、引脚选择、构建和下载由本对话负责；不要修改 FPGA 仓库的 Verilog、ARM 分析器、屏幕驱动、引脚约束或 SD 启动文件。若发现 FPGA 不兼容，提交源参数、预期与实际波形证据给用户转交原对话，不迎合解码结果篡改合法协议。

开始前先检查用户提供的开发板资料、现有工程与工具，再一次性确认缺失的芯片完整型号、板卡型号/版本、晶振/时钟、下载器、可用接口、按键/LED和开发工具。**目前尚未指定 STM32 型号，不得默认 STM32F103，不得先写死 PA9/PB6 等引脚。** 优先复用可构建的现有工程；没有工程时再选择适配该型号的 HAL/LL/寄存器和工具链。无须 Linux、RTOS、图形上位机或联网功能。

用户电脑只有一个空闲 USB-A 口，另一个接鼠标。STM32 程序下载后必须能在没有电脑串口命令的情况下选择基础测试、启动/停止和重复输出；不要求 STM32 与 FPGA 同时连接电脑才能工作。具体独立供电方式按实际板卡资料确定。

## 2. 被测 FPGA 当前能力和限制

| 项目 | 当前实现 |
|---|---|
| 主板 | 正点原子领航者 ZYNQ7010 |
| 主项目 | `E:\FPGAproject\FPGA2026`，GitHub：<https://github.com/chronox142857/FPGA2026> |
| 架构 | Verilog 采样/触发/BRAM，板上 ARM 裸机 C 识别与解码，ST7735S 128×128 小屏 |

| 采样率 | 1、5、10、25、50 MSa/s |
| 触发 | 立即、指定通道上升/下降沿、电平组合；预触发 0/25/50/75% |
| UART | 正常极性，空闲高，8N1，9600～1000000 baud |

| 歧义 | SPI允许多个模式/收发方向候选，不能要求任意波形唯一识别方向或CPHA |

已有同板回接结果：UART 115200 的100次正常和8次坏停止位核对；SPI 100kHz四模式/四预触发/自动与手动共32组。I²C尚无实物通过记录。STM32使用自身时钟，目的是补独立设备和异步相位验证。

这里的“协议识别”指UART/I²C/SPI底层协议。下文测试包的同步字、编号和校验只是核对数据用，FPGA目前不会自动理解自定义业务帧，也不负责校验本测试包的XOR。不要新造一种电气/位时序协议代替三类标准协议。

## 3. 电气与接线约定

使用与当前 FPGA 输入匹配的 **3.3V 数字逻辑并共地**。FPGA只监听，不能把5V TTL、RS232、RS485差分线直接接到输入。双方独立供电时不随意互接电源输出。

以下仅规定FPGA侧，STM32侧引脚由实际型号与外设复用决定，并在最终接线表中填写。

| 信号 | FPGA通道 | J3丝印球位 |
|---|---|---|
| UART TX / I²C SCL / SPI SCK | CH0 | W18 |
| I²C SDA / SPI MOSI | CH1 | W19 |
| SPI MISO（存在时） | CH2 | R16 |
| SPI CSn | CH3 | R17 |
| 可选同步标记 | CH4 | W20 |
| 可选GPIO测试 | CH5/6/7 | V20/P18/N17 |
| 公共参考 | GND | 板上GND |

W18等是封装球位对应的J3丝印，不是排针序号。不要动小屏的V17、V18、T17、R18、Y18、Y19接线。以后换RGB屏时采集引脚可能重新分配；信号源使用逻辑信号名，不把FPGA球位写进STM32输出逻辑。

**接外部源前必须断电移除原板载回接线：P15→W18、P16→W19、V16→R16、W16→R17。** 这些旧线会把FPGA发生器输出接到同一输入，不能与STM32输出并联；FPGA发生器保持关闭。串口 `test 0 0` 修改的是下一次采集配置，需要执行一次 `run` 才写入发生器寄存器，不能把只修改菜单当成已经停掉实际输出；`stop`取消采集和循环，也不单独关闭已运行的发生器。可在断开外部源时设置 `loop 0`、`test 0 0`，再 `run`、`stop`，或使用默认发生器关闭的完整冷启动。接口只是监听输入，不向STM32提供ACK或MISO。

I²C的SCL/SDA采用开漏输出与外部上拉，不能把内部弱上拉当成已满足高速时序。用户目前只有杜邦线，没有已确认的外接上拉电阻；先查STM32板/模块是否已有上拉。短线100kHz可从两只约4.7kΩ上拉至3.3V开始评估，更高速度按实际负载/上升沿核对，不能保证同一电阻适合1MHz。材料不足要报告阻塞项，UART/SPI可先做。

## 4. 交付优先级与基础操作

### P0：先交付可独立操作的低速闭环

1. UART 115200、8N1正常已知数据。
2. SPI约100kHz、模式0～3、8位MSB先发、软件CS覆盖完整事务。
3. I²C 100kHz、地址0x50的写事务；扩展读、重复START、ACK/NACK案例。
4. 静态高/低电平，作为UNKNOWN测试输入。
5. 正常信号先通过源侧时序检查，再与FPGA联调。P0不以最高速度或大量附加功能作为开始联调的门槛。

至少提供 `STOP`、`UART_NORMAL`、`I2C_WRITE`、`SPI_MODE0/1/2/3`、`STATIC_LOW/HIGH` 档。上电默认STOP，协议切换只在停止后执行。按实际板上按键设计选择/启动方式，例如短按选择、长按启动/停止；用LED闪烁/文档说明当前档位，无须LCD。缺少按键时提供经确认的替代输入，并可编译选择上电延时自动运行的单一测试档，不能强依赖电脑串口。

### P1：补全验收范围

- UART完整速率表、坏停止位、窗口截断激励。
- I²C 400kHz/1MHz（实际硬件与上拉条件允许时）、读/重复START/NACK/截断。
- SPI更高频率、短事务/长事务、异常CS提前释放、不同数据图样。
- 确定的GPIO脉冲、通道组合和可选8路图样，用于触发/时间/掩码验证。

不支持的速率必须在能力表中注明原因和可实现替代值，不能把目标频率写进日志就算实现。无上拉、无从机、引脚冲突、工具缺失等分别记录；不要为了绕开缺项改用不符合协议的推挽I²C或浮空MISO。

## 5. 数据与预期结果格式

正常数据建议使用统一的8字节核对包，便于跨协议比较。该格式是项目测试约定，不是行业协议要求。

| 字节 | 内容 |
|---|---|
| 0..1 | 固定 `55 AA` |
| 2 | CASE_ID |
| 3..4 | 16位递增包序号，低字节先发，0开始，65535后回绕 |
| 5 | `pattern[seq & 7]` |
| 6 | `pattern[(seq + 3) & 7]` |
| 7 | 前7个字节逐字节XOR |

`pattern = {00, FF, 55, AA, 01, 80, 7E, 81}`。序号只在本包实际完成输出后递增，每次明确开始一个新测试从0重置；无限循环、固定次数和固定序号重复模式要区分。异常用例保留原始预期包，再单独注明哪一位、哪个ACK或哪次CS被破坏，不把异常后的实际字节冒充正常预期。

UART正常CASE_ID=11时，序号0、1、2的完整期望包依次为：

```text
55 AA 11 00 00 00 AA 44
55 AA 11 01 00 FF 01 11
55 AA 11 02 00 55 80 39
```

| CASE_ID（十六进制） | 用例 |
|---|---|
| 11 / 12 | UART正常 / 坏停止位 |
| 21 / 22 / 23 / 24 | I²C写 / 读与重复START / NACK / 截断 |
| 30..33 | SPI模式0..3正常 |
| 34 | SPI事务提前释放CS，模式另列 |
| 40 / 41 / 42 | 静态低 / 静态高 / GPIO触发图样 |

若实际设备使某一I²C读数据不能采用此包，允许提供固定已知读数据或明确的寄存器映射，但必须另列该案例逐字节预期，不能假定硬件传感器读数固定。SPI正常MOSI采用此包；MISO采用预先准备的本包逐字节按位取反，仅在源实现能保证该模式时启用。MOSI回接MISO时两方向相同，必须标明，不应用互补预期。

每个CASE交付一条机器可读记录（JSON或CSV），至少含：固件版本、MCU型号/时钟来源、CASE_ID、协议、生成方式（硬件外设/定时器DMA/GPIO模拟）、引脚映射、请求与配置计算得到的实际速率、是否有仪器实测、SPI模式、I²C地址、数据序号/预期字节、间隔、重复次数、异常位置、接线/从机/上拉要求。未用仪器测量时只能称计算速率，不能填“实测”。

## 6. UART要求

- 正常极性、空闲高、8数据位、无校验、1停止位，UART数据位LSB先发。
- P0=115200；P1目标=9600、19200、38400、57600、115200、230400、460800、921600、1000000 baud。逐档报告时钟、分频和理论误差；超出型号能力或误差过大则报告，不伪装通过。
- 正常包内连续发送8字节，包间默认空闲32个位周期，支持修改；不用固定几十毫秒大间隔代替所有档位，否则高采样率窗口可能只录到空闲。
- 正常发送优先硬件UART；打印日志不能混到被测TX上。调试串口与信号输出分开，或输出期间停用调试打印。
- 坏停止位用例以较低速率先实现（建议9600/115200）：保持明确的位周期，只将选中字节的停止位拉低，之后恢复合法空闲及后续字节；记录字节序号、坏停止位位置和恢复方式。普通硬件UART若不能构造，使用独立定时器/GPIO/DMA输出并标明，不将BREAK冒充单个坏停止位。
- 额外提供连续包列，供FPGA在任意位置开始/结束采样，验证窗口边界；源本身正确与采集窗口造成的截断分别标记。坏帧比例可能使FPGA自动模式返回UNKNOWN，按手动参数检出错误也要单独记录。

## 7. I²C要求

- 7位地址0x50，线路上的写地址字节为A0、读地址字节为A1；交付时明确HAL参数是否需要移位，不能将8位线路地址直接当作7位地址。
- P0=100kHz，P1=400kHz/1MHz。先确认型号是否支持Fast-mode Plus、所选引脚及电气条件是否满足，不能默认所有STM32支持1MHz。
- 至少实现下列可选用例并分别标注源类型：

| 用例 | 线路事件和预期 |
|---|---|
| 正常写 | START → A0/ACK → 8字节已知包、每字节ACK → STOP |
| 读与重复START | START → A0/ACK → 寄存器00/ACK → RESTART → A1/ACK → 8字节已知读数据；主机对前7字节ACK、最后1字节NACK → STOP |
| 地址NACK | START → A0/NACK → STOP，无假装已经发送成功的后续数据 |
| 数据NACK | 指定数据字节被NACK，随后按预定流程STOP，注明前面已完成的字节 |
| 截断 | 指定字节少于8位或缺第9个应答时钟后停止，记录位置；恢复线路并留空闲 |

**读事务最后一字节NACK是正常结束，不等同于通信故障。** FPGA会显示NACK标志，不能要求一律显示帧错误。

只有一个I²C主机、没有从机时，合法结果通常是地址NACK，不能期待FPGA监听器提供ACK。允许以下实现路线：

1. 实际STM32主机+可用已知从机，或同一STM32上两个可用I²C外设分别作主从并以外部线相连；提供从机初始化和预期数据。
2. 没有从机时，用定时器/GPIO开漏模拟整条总线，包括ACK和读数据，明确标成“模拟总线源”，用于解析验证；之后再补真实外设主从兼容测试。

SDA的普通数据只在SCL低时变化；SCL高时的数据变化仅用于START/STOP。每字节8位+第9位应答，读写数据均MSB先发。默认不拉伸时钟；若增加clock stretching用例，要独立编号，不混入第一轮基线。阶段1包/事务间默认空闲32个SCL周期，可配置并导出实际间隔。

## 8. SPI要求

- 低有效CS、8位、MSB先发。四模式如下：

| 模式 | CPOL | CPHA | 采样沿 | 数据变化沿 |
|---|---|---|---|---|
| 0 | 0 | 0 | 上升 | 下降 |
| 1 | 0 | 1 | 下降 | 上升 |
| 2 | 1 | 0 | 下降 | 上升 |
| 3 | 1 | 1 | 上升 | 下降 |

- P0约100kHz，P1逐步提高到约500kHz、1MHz、2MHz、最高5MHz。硬件分频不一定能恰好得到这些值；报告实际可达频率，不超过被测目标上限且不把4.5MHz写成5MHz验收通过。需要精确5MHz时再判断是否能安全调整外设时钟。
- CS下降前SCK已经处于CPOL对应空闲电平；CS建立、末位数据保持、CS高间隔必须有明确配置，基线可分别留至少2、2、32个SCK周期。模式0/2首位在第一个采样沿前有效，模式1/3保留完整第一移位沿；最后一个完整时钟周期结束且SCK回到空闲后再释放CS。
- 每个CS低区间默认输出一份8字节包，不能自动把NSS在每字节之间拉高；另提供1/2字节短事务与可配置长事务。
- 优先硬件SPI主机。MISO必须有已知驱动：真实从机/同芯片另一SPI外设作从机/经过定时器产生的同步模拟输出。需要互补数据时在事务前装好从机发送缓冲，保证CS首字节已就绪。
- 只有主机时可先将MOSI回接到主机MISO并让FPGA监听两路，此时预期RX=TX，单独标明“回环”；也可先作MOSI单方向人工核对，但当前FPGA自动SPI枚举需要4个候选通道，浮空MISO不能作为完整四线自动识别验收。
- 截断用例选择在一字节的第3或第5个采样沿之后提前释放CS，记录实际位数。普通完整事务末尾的采集窗口截断是另一回事，不能算源产生异常。
- 自动识别允许AMBIGUOUS；以正确模式/角色进入候选集合和手动逐字节核对为分开的检查项，不要求从任何数据中唯一判定MOSI/MISO或CPHA。

## 9. 采样窗口、同步与附加激励

源不依赖FPGA提供应答、握手或同步时钟。连续输出短事务便于任意时刻触发；也应能停止、单次有限包列、重置序号，保留足够空闲作为边界。软件控制频率时用硬件时钟/定时器计算，不依赖未标定的空循环；高频时按型号选DMA/外设，避免中断和打印破坏波形。

FPGA当前识别规则要求每bit或SCK周期至少10个采样点；还要让窗口容纳完整事务及边界，不能只满足采样比。

| 信号目标 | 首轮建议FPGA采样率 | 32768点窗口 |
|---|---|---|
| UART 9600/19200/38400/57600 | 1MSa/s | 32.768ms |
| UART 115200～460800 | 5MSa/s | 6.5536ms |
| UART 921600/1M | 10MSa/s | 3.2768ms |
| I²C/SPI 100kHz | 5MSa/s | 6.5536ms |
| I²C 400kHz/1MHz | 10/25MSa/s | 3.2768/1.31072ms |
| SPI 500kHz/1MHz | 10/25MSa/s | 3.2768/1.31072ms |
| SPI 2MHz/5MHz | 25/50MSa/s | 1.31072/0.65536ms |

表中UART高速窗口可能超过128条目；用已知包与递增序号检查保留的完整条目，同时记录溢出，不要求小屏展示整个窗口的全部字节。UART自动模式至少需要3个有效字节。完整采集可能从包中间开始，不能要求每次第一个结果一定是55。

可选SYNC标记在一个事务开始前变高、结束后变低，信号用途和提前量写清楚，SYNC不参与协议候选通道；默认使用UART TX下降沿或SPI CS下降沿即可触发。需要检测I²C START时应注意SDA普通下降沿不等于START，首轮可先立即触发。

P1附加GPIO测试：稳定高/低、已知频率及不同脉宽脉冲、4路/8路计数图样和指定电平组合。给出周期、相位、脉宽、更新方式与预期状态序列，用于输入通道、触发、掩码和量化误差核对。不要将任意PWM/随机序列都强制判为UNKNOWN，因为某些波形本身可能存在合法协议解释。

## 10. 交付物与验收

交付目录由用户指定，放在 `E:\FPGAproject` 下独立信号源文件夹，避免覆盖 `FPGA2026`。开始开发前确认具体路径；无须为此改动现有FPGA工程。

至少交付：

1. 可构建完整源工程、必要启动文件/链接脚本/配置文件，标明工具和HAL/SDK版本；使用Cube生成时保留.ioc。
2. 已构建ELF/HEX/BIN及构建日志，说明下载方法和独立供电/复位/按键操作。
3. `README.md`：先跑通P0的最短操作、引脚表、模式表、已实现/未实现及限制。
4. `CASES.json`或CSV：上述机器可读参数、预期字节、异常位置和计算速率；给出序号0、1、2的具体期望值及生成公式。
5. `VALIDATION.md`：区分代码完成、编译通过、源侧实测、FPGA联调通过；没有实际板子/仪器时明确待验证。
6. 一份交给FPGA对话的联调说明：CASE_ID、源固件版本、接线、上拉/从机、采样率建议、预期协议/字节/事件、允许歧义及异常。

每个基础用例按“源侧已知输出 → FPGA采样原始数据 → 协议候选/手动解码 → 已知数据核对”验收。不能仅凭STM32串口打印成功或FPGA屏幕出现协议名判为通过。数据/时间核对存在差异时保留原始记录并报告，不把错误计数清零或调整源迎合当前解码器。

完成P0后先交可用版本，再补P1。需要新增硬件、调整协议范围或更改既定测试包时先说明具体原因与影响；不要默默省略ACK、时钟边沿、CS或异常用例。
